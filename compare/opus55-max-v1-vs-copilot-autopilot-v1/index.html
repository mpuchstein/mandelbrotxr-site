The reviewers' one-line reasons, verbatim

A Opus 5.5 · v1

  • Done-when fulfilment 8 — Immersive VR and AR sessions place a 3D Mandelbrot heightfield "hologram" on a pedestal in a sky-domed arena; iPhones get a gyro and Cardboard fallback. It is an open arena, not an enclosed room.
  • Device/XR compatibility 8 — No required features, local-floor→local fallback, optional hand-tracking, transient-pointer, screen-space AR with hit-test and dom-overlay, xr-standard gamepads, WebGL2 float-format fallbacks.
  • Visual wow effect 9 — GPU perturbation deep zoom (~43 octaves), distance-estimate terrain, procedural nebula cubemap with env reflections and fresnel, ACES tonemap, palette cycling, glows, particles, build/scan animations, Julia inset.
  • Usability & controls 8 — Clear landing page, per-input-type help, a world-space panel that follows the head, grab-pan, two-hand zoom and rotate, tap-to-dive, history, guided "Dive" tour, haptics, audio. No comfort vignette.
  • Code quality & robustness 7 — Strong engineering (async PBO readback, adaptive GPU budget, scissored progressive rendering), but dense one-liner style, a leaked XR session on the error path, synchronous CPU probes and leftover debug hooks.
  • Prompt adherence 9 — Truly standalone: one file with zero external requests (raw WebGL2 + WebXR, no three.js) and an XR-first design.

B Copilot Autopilot · v1

  • Done-when fulfilment 2 — The XR render loop throws after its first frame (frame parameter shadows the function, l.163/167), so no device gets a working immersive room. Only the non-XR orbit view works.
  • Device/XR compatibility 3 — It asks for immersive-vr/immersive-ar with xrCompatible, but local-floor is required with no fallback, there is no XR input at all, AR is cleared opaque, and iPhone gets only the flat fallback.
  • Visual wow effect 3 — A 120×120 CPU heightfield in three hard colour bands, simple diffuse/rim shading, 650 point "stars" and a flat floor plane. The viewer spawns under a plateau 1.85 m high.
  • Usability & controls 3 — The landing panel is good-looking, but XR has no controls, no exit button and no locomotion. The hint promises pinch-zoom that isn't implemented, and Explore mode has no way back to the menu.
  • Code quality & robustness 3 — Compact raw WebGL2 with shader error checks. But it has a fatal shadowing bug, a per-view full-framebuffer clear, no try/catch in enter(), canvas resize on every frame, and a stale XR framebuffer binding.
  • Prompt adherence 6 — A true single file with no dependencies that uses WebXR, but it falls far short of "highest possible wow" and the "virtual room".

  • Visual wow 8 — The holographic tabletop, palettes and live Julia inset are striking, and deep zoom (≈1e6×) holds detail. Spiky "grass" aliasing at the boundary, faceted interiors and terraced slabs in Immerse take some of the polish off.

  • XR readiness & messaging 7 — Feature-detects with isSessionSupported and hides VR/AR when they're unsupported. A plain-language note offers the browser fallback, and phone-only "Look around" and "Cardboard" modes exist in the DOM. B Copilot Autopilot · v1

  • Loads & renders 7 — Clean load with zero console messages and a WebGL2 canvas; the start card shows in under a second, and the 3D scene appears only after "Explore on screen".
  • Done-when (desktop-checkable) 4 — A 3D Mandelbrot heightfield sits on a floor under a starfield, but there is no "room", and on this desktop the XR path is a silent dead end.

Clicking one does tell the user it is unsupported ("VR is not supported on this device." / "AR is not supported on this device."), but in a blocking native alert() rather than in-page UI, and with no hint of what to do instead.
