Browser review reviewed blind as candidate-02

8 / 10 overall

The reviewer’s overall-score line — REVIEW.md line 38 GitHub

Browser review criteria with the reviewer's one-line reasons, verbatim.
CriterionScoreOne-line reason (verbatim)
Loads & renders9Single inline script, FCP ≈ 68 ms on reload, a 3D scene is live behind the landing card at once, no console messages at all.
Done-when (desktop-checkable)8A real room (starfield and nebula sky, grid floor, pillars, glowing rings) with a raised 3D Mandelbrot height field on a pedestal. A clear XR path exists in code (Enter VR/AR buttons), but they are hidden here, so I couldn't exercise that path.
Visual wow8The holographic tabletop, palettes and live Julia inset are striking, and deep zoom (≈1e6×) holds detail. Spiky "grass" aliasing at the boundary, faceted interiors and terraced slabs in Immerse take some of the polish off.
Usability & controls7Clear hint line, readable Re/Im/Zoom HUD, named locations ("Seahorse Valley"), and every button works. No keyboard navigation, Home doesn't reset the camera orbit, and the phone toolbar hides half its buttons behind a horizontal scroll with no affordance.
Robustness8Zero console errors or warnings. Resizes cleanly with no page scroll. 60 fps across every mode on re-test, though one early session ran at ~2 fps that I couldn't reproduce.
XR readiness & messaging7Feature-detects with isSessionSupported and hides VR/AR when they're unsupported. A plain-language note offers the browser fallback, and phone-only "Look around" and "Cardboard" modes exist in the DOM. The note says "no WebXR" even though navigator.xr exists (it's really "no XR device").

Special elements noted

Bullets from the judges’ “Special elements” sections that name this candidate, quoted verbatim. Letters are the judge’s blind labels. All elements, grouped by technique, are in the techniques catalog.

  • H, E — perturbation-theory deep zoom (float64 CPU reference orbit in an RG32F texture, float32 GPU deltas, row-scissored progressive jobs, cross-faded buffers): the only candidates that zoom past float32 limits, to roughly 1e-12 to 1e-13.

    HTML judge · H = this candidate; E = Opus 5.5 · v0 — RANKING.md line 27 GitHub

  • H — van Wijk & Nuij smooth zoom-pan flights plus async PBO readback with fenceSync for ray-casting the hologram: no other candidate does stall-free GPU→CPU readback or optimal zoom-pan paths.

    HTML judge · H = this candidate — RANKING.md line 28 GitHub

  • H — handheld-AR detection via interactionMode === 'screen-space' with hit-test reticle placement: the only phone-AR flow that places the model on a detected real surface.

    HTML judge · H = this candidate — RANKING.md line 29 GitHub

  • H, E, G — Cardboard/split-screen phone stereo: the only route to a stereo "headset" view on iPhones, where WebXR doesn't exist.

    HTML judge · H = this candidate; E = Opus 5.5 · v0; G = GPT6 Pro · v0 — RANKING.md line 30 GitHub

  • E — the rendering algorithm prototyped in Python before writing shaders: an fp32 perturbation renderer was compared with float64 (mean height error 0.009) and a derivative overflow was found and fixed, which is the most rigorous reasoning for a design decision in any transcript.

    Transcript judge · E = this candidate — RANKING.md line 30 GitHub

  • E — tour targets verified with Newton's method and rendered contact sheets: it computed the exact period-3 nucleus and dropped c = i as "just a single filament", choosing the deep-zoom destinations by evidence rather than by folklore.

    Transcript judge · E = this candidate — RANKING.md line 31 GitHub

  • E — the trigger-tap open issue reported and then fixed: it reported the emulator tap failure as an open issue rather than hiding it, then fixed it and re-tested; widening the window to 4 frames is partly tuned to the emulator, though.

    Transcript judge · E = this candidate — RANKING.md line 32 GitHub

  • E and F — explicit "Not verified" sections: both list untested hardware, modes and features, which is the calibration standard the shorter transcripts lack.

    Transcript judge · E = this candidate; F = Opus 5.5 · v0 — RANKING.md line 33 GitHub

  • A, B — perturbation deep zoom: both compute a float64 reference orbit on the CPU, upload it as an RG32F texture and iterate fp32 deltas with Zhuoran rebasing on the GPU, which goes orders of magnitude deeper than every other candidate's naive float32 escape-time.

    HTML + Transcript judge · A = Opus 5.5 · v0; B = this candidate — RANKING.md line 26 GitHub

  • B — Julia inset at the pointer: a live Julia-set panel driven by whatever point the controller, gaze or mouse is aiming at adds real mathematical insight on top of the visual effect.

    HTML + Transcript judge · B = this candidate — RANKING.md line 29 GitHub

  • B — AR hit-test placement: it is the only candidate that requests hit-test and shows a surface reticle for placing the hologram on handheld Android AR.

    HTML + Transcript judge · B = this candidate — RANKING.md line 30 GitHub

  • A, B — multi-turn completion: both hit tool limits and needed two or three user "Continue" prompts before delivering, which counts against them as a usability cost but not against the deliverable.

    HTML + Transcript judge · A = Opus 5.5 · v0; B = this candidate — RANKING.md line 40 GitHub

  • A — Live Julia-set inset ("Julia set at the pointer"): it updates as you hover the Mandelbrot terrain, adding real mathematical insight on top of the visuals.

    Browser judge · A = this candidate — RANKING.md line 28 GitHub

  • C, G, H, A — Guided tour / destination flights to Seahorse Valley: animated flights to famous regions make deep zoom discoverable for first-time users.

    Browser judge · C = Opus 5.5 · v0; G = GPT6 Pro · v0; H = GPT6 Pro · v1; A = this candidate — RANKING.md line 31 GitHub

  • G, perturbation deep zoom: a float64 CPU reference orbit with Zhuoran rebasing let the Dive button run to 1.96×10¹⁰ while the terrain still rendered, far past the roughly 10⁵ limit where plain float32 shaders break down.

    Browser + HTML judge · G = this candidate — RANKING.md line 27 GitHub

  • G and H, local-floor/hit-test/dom-overlay session setup with Cardboard and gyro fallbacks: both pick features per mode and hide unsupported buttons, so each phone class gets a working path.
