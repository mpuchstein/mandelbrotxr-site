HTML review criteria with the reviewer's one-line reasons, verbatim.
CriterionScoreOne-line reason (verbatim)
Done-when fulfilment8Quest/Pico/PCVR enter an immersive-vr room with a 3D escape-time relief. Android gets immersive-ar (a 6DoF window into the room). iPhone gets a non-immersive touch/gyro 3D view, the best available without WebXR on iOS.
Device/XR compatibility8VR+AR, local-floor→local fallback, hand-tracking, transient-pointer, gaze-dwell, snap turn, teleport, secure-context and iOS motion-permission handling. AR is opaque and dom-overlay is dead code.

Usability & controls7Polished 2D UI, presets, help/XR dialogs, a 9-button in-world panel with grip-summon. In XR you can only zoom at the centre, and the set's plateau sits above eye height.
Code quality & robustness7Worker + main-thread fallback, cancellation tokens, adaptive quality, error mapping, disposal. But the app code ships minified, with about 120 un-instanced room draw calls and some dead paths.
Prompt adherence9One self-contained 656 KB file with three.js r186 embedded, zero network requests, WebXR as asked.

Expected deliverable quality8A self-contained 641 KB file with embedded Three.js, a real escape-time landscape, 4 destinations, an in-room XR menu, teleport/snap-turn and phone fallbacks. Likely solid, though the visual "wow" depends on how good the heightfield looks.

Browser review reviewed blind as candidate-01

8 / 10 overall

The reviewer’s overall-score line — REVIEW.md line 35 GitHub

Browser review criteria with the reviewer's one-line reasons, verbatim.
CriterionScoreOne-line reason (verbatim)
Loads & renders9A finished 3D frame appears in under 1 s, with zero console messages (errors or warnings) across the whole session. It is one self-contained inline script on WebGL 2 with no CDN dependencies.
Done-when (desktop-checkable)8It is a real room: a circular observatory with pillars, rings, wall typography, a plinth and a 3D escape-time heightfield of the set. The XR path exists (a hidden "Enter AR" button and a device-capability dialog), but entering XR can't be confirmed without a device.
Visual wow effect8The overview is striking: neon contour lines, glowing rings, layered terraces and three good palettes. It is weaker at zoomed destinations, where a square slab overhangs the round plinth and the set interior is a dark flat plateau.
Usability & controls8Destinations, palette, orbit, zoom, home, sliders, walk mode, keyboard shortcuts and an excellent help sheet all work. The zoom buttons can drop you into a featureless flat area, and the HUD copy overlaps text in the 3D scene.
Robustness7No errors, the canvas tracks resizes, and Home/R recovers from any state. Fullscreen didn't engage here and gave no feedback, a first H press was swallowed by button focus, and frame rate couldn't be measured (the harness throttled requestAnimationFrame).
XR readiness & messaging9The "XR info" dialog lists 3D room / VR / AR / Connection status and explains HTTPS, Quest/PICO/Steam Frame/iPhone support and in-headset controls (teleport, snap turn, gaze-dwell). The Enter buttons are hidden when unsupported, and the copy is clear and honest.

    HTML + Transcript judge, ranking justification for E, verbatim — RANKING.md line 18 GitHub
  4. 1/ 8

    Browser judge · hands-on in a browser

    Rank 1 of 8 · saw this candidate as letter H · judged against prompt v1

    Polished glowing observatory with contour-traced terrain. Destinations, palette, double-click dive and a rich Controls panel (walk, motion look, sound, gentle motion). Exemplary "XR info" capability dialog. ARIA labels throughout and a clean phone layout. No console errors.

  5. 3/ 8

    Best-looking room: a lit gallery rotunda, a contour-lined pedestal and a polished HUD. The XR-info dialog explains device support; phone layout is clean; the settings panel is rich. Zoom is shallow (about 187×), and Seahorse renders as a large flat plateau.

  • A and D — cited device-compatibility tables: both decline to promise Steam Frame or iOS immersive support and point to vendor and WebKit sources, which handles the device list honestly.

    Transcript judge · A = GPT6 Pro · v0; D = this candidate — RANKING.md line 34 GitHub

  • D — fixes driven by the emulator view: moving the VR menu once the stereo test showed it hiding the sculpture is a good example of verification feeding back into usability.

    Transcript judge · D = this candidate — RANKING.md line 36 GitHub

  • E — gaze-dwell and ambient sound: a dwell-to-select fallback for input-less headsets, plus WebAudio ambience, are usability and atmosphere touches that most of the others lack.
