    Browser review — REVIEW.md line 17 GitHub

  • Major: the unsupported-XR path is a blocking alert() behind always-enabled buttons. Evidence: steps 3–4b. isSessionSupported returns false for both modes, yet the buttons stay enabled. Clicking one does tell the user that VR or AR is unsupported, but through a native modal ("localhost:8704 says: VR is not supported on this device.", seen by the operator and confirmed via the alert stub). The modal freezes the page, wedges browser automation, and doesn't say what to do instead (use a headset browser, HTTPS, or Explore on screen). A disabled or relabelled button would avoid the dead-end click altogether. Fix: check support at load, then disable or relabel each button ("VR needs a headset browser / HTTPS"). Show errors inline on the card instead of using alert(), and wrap requestSession in try/catch.

Open on a device

Scan to open the product on a phone or headset browser. The code encodes the product's absolute URL:

https://mandelbrotxr.puchstein.dev/play/copilot-autopilot-v1/

WebXR sessions need HTTPS and a browser with WebXR support (for example the Meta Quest Browser or Chrome on Android). No headset session was entered during the experiment; see the caveats.

Code quality & robustness3Compact raw WebGL2 with shader error checks. But it has a fatal shadowing bug, a per-view full-framebuffer clear, no try/catch in enter(), canvas resize on every frame, and a stale XR framebuffer binding.
Prompt adherence6A true single file with no dependencies that uses WebXR, but it falls far short of "highest possible wow" and the "virtual room".
