Expected deliverable quality8One 650 KiB offline HTML file with three.js inlined: perturbation deep zoom, a terrain on a plinth, a wall screen, a panel usable from VR, gyro and Cardboard modes. Real-headset performance and the layers path are unknown.

Browser review criteria with the reviewer's one-line reasons, verbatim.
CriterionScoreOne-line reason (verbatim)
Loads & renders9Fully self-contained (~666 KB, no network requests), DOMContentLoaded at 144 ms, the 3D room is visible behind the intro card right away, and the console stays empty.

XR readiness & messaging9XR buttons appear only when isSessionSupported is true, and the status line says plainly that no runtime answered. It requests local-floor and hand-tracking, and the in-world tablet and controls board cover headset use.

Special elements noted

Bullets from the judges’ “Special elements” sections that name this candidate, quoted verbatim. Letters are the judge’s blind labels. All elements, grouped by technique, are in the techniques catalog.

  • H, E — perturbation-theory deep zoom (float64 CPU reference orbit in an RG32F texture, float32 GPU deltas, row-scissored progressive jobs, cross-faded buffers): the only candidates that zoom past float32 limits, to roughly 1e-12 to 1e-13.

    HTML judge · H = Opus 5.5 · v1; E = this candidate — RANKING.md line 27 GitHub

  • H, E, G — Cardboard/split-screen phone stereo: the only route to a stereo "headset" view on iPhones, where WebXR doesn't exist.

    HTML judge · H = Opus 5.5 · v1; E = this candidate; G = GPT6 Pro · v0 — RANKING.md line 30 GitHub

  • E — deletes XRWebGLBinding.prototype.createProjectionLayer when the session didn't grant layers: an unusual, targeted workaround for a three.js r186 projection-layer pitfall that no one else addresses.

    HTML judge · E = this candidate — RANKING.md line 31 GitHub

  • E — context "wall screen" at 3× the terrain span: the only candidate that shows where you are in the set while you're zoomed in.

    HTML judge · E = this candidate — RANKING.md line 32 GitHub

  • F — the three.xr.js substitution: it names the archive date, the obsolete WebVR APIs (getDisplays, vrdisplaypresentchange) and the pinned three.js r186 WebXRManager replacement, which is the most evidence-backed answer to the v0 stack requirement.

    Transcript judge · F = this candidate — RANKING.md line 26 GitHub

  • F — GPU-vs-CPU accuracy check and the shipped compareWithCPU() hook: it compares 400 random points per view with median and p95 iteration errors, and the hook lets the user rerun that check on any view, which turns "the fractal is correct" into a measured claim.

    Transcript judge · F = this candidate — RANKING.md line 27 GitHub

  • F — it corrected its own overclaiming copy: it noticed the intro text overstated the zoom depth and rewrote it to match the real limit, which is rare self-policing of marketing-style claims.

    Transcript judge · F = this candidate — RANKING.md line 28 GitHub

  • F — a first turn with no visible reply: after about 25 research tool calls the turn ended with only hidden reasoning, a handoff failure that left the user with nothing.

    Transcript judge · F = this candidate — RANKING.md line 29 GitHub

  • E and F — explicit "Not verified" sections: both list untested hardware, modes and features, which is the calibration standard the shorter transcripts lack.

    Transcript judge · E = Opus 5.5 · v1; F = this candidate — RANKING.md line 33 GitHub

  • A, B — perturbation deep zoom: both compute a float64 reference orbit on the CPU, upload it as an RG32F texture and iterate fp32 deltas with Zhuoran rebasing on the GPU, which goes orders of magnitude deeper than every other candidate's naive float32 escape-time.

    HTML + Transcript judge · A = this candidate; B = Opus 5.5 · v1 — RANKING.md line 26 GitHub

  • A — prototype monkey-patch: when the session didn't grant layers, it does delete XRWebGLBinding.prototype.createProjectionLayer to stop three.js r186 using projection layers, a bold low-level compatibility hack that no other candidate tried.

    HTML + Transcript judge · A = this candidate — RANKING.md line 27 GitHub

  • A, D — three.xr.js substitution: both recognised that the requested three.xr.js is archived WebVR-era code and replaced it with three.js's native WebXRManager, explaining why (D even documents it in the in-page guide), which is the right reading of an outdated v0 requirement.

    HTML + Transcript judge · A = this candidate; D = GPT6 Pro · v0 — RANKING.md line 28 GitHub

  • A, B — multi-turn completion: both hit tool limits and needed two or three user "Continue" prompts before delivering, which counts against them as a usability cost but not against the deliverable.

    HTML + Transcript judge · A = this candidate; B = Opus 5.5 · v1 — RANKING.md line 40 GitHub

  • C — In-world controls signage and a plinth-side tablet panel: these put the help text and buttons inside the 3D room where a headset user can reach them, rather than in a DOM overlay XR cannot show.

    Browser judge · C = this candidate — RANKING.md line 29 GitHub

  • C, G, H, A — Guided tour / destination flights to Seahorse Valley: animated flights to famous regions make deep zoom discoverable for first-time users.

    Browser judge · C = this candidate; G = GPT6 Pro · v0; H = GPT6 Pro · v1; A = Opus 5.5 · v1 — RANKING.md line 31 GitHub

  • H, deep tour with float64 reference orbit and PBO readback: the tour stop "Seahorse valley" at width 3×10⁻⁹ rendered crisp spirals on both the wall screen and the terrain, and async readback keeps ray-picking from stalling the frame.

    Browser + HTML judge · H = this candidate — RANKING.md line 28 GitHub

  • H, wall-screen map with a viewport rectangle: projecting the current window onto a wall-sized 2D map turns the room itself into the navigation aid.

    Browser + HTML judge · H = this candidate — RANKING.md line 29 GitHub

  • G and H, local-floor/hit-test/dom-overlay session setup with Cardboard and gyro fallbacks: both pick features per mode and hide unsupported buttons, so each phone class gets a working path.
